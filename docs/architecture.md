## 依赖方向

- 启动装配连接各包，依赖由装配层指向内部包。
- HTTP adapter 调用生成编排、资源池和存储，业务包独立于 HTTP adapter。
- 生成编排协调资源池与上游协议，后两者彼此独立。
- 资源池调用存储和 Cookie 规则，存储保持为独立的基础能力。
- 上游协议调用 Cookie 规则和基础传输；账号选择与数据库访问分别归资源池和存储负责。
- 配置包提供快照；数据库持久化与模型可用性校验由生成编排协调。

账号检测和保活跨越账号状态与上游网络，放在生成编排中。资源池决定使用哪个账号和出口；
协议包负责发出指定凭据与出口的请求；编排在结果返回后协调写回。这样避免循环导入，
同时保留原有账号—出口绑定、身份保护及失败归责规则。

数据库连接和方言属于同一存储包，集中处理 SQLite、MySQL、PostgreSQL 的差异，
沿用现有 schema 与升级语句。

## 状态与生命周期

应用状态和缓存按单进程生命周期管理。
启动配置仅在初始化时修改；运行时配置通过加锁的快照读取和原子发布更新，锁与存储值保持私有。
数据库仍在进程内惰性打开，SQLite 保持单连接，结束时可关闭连接。

凭据缓存、传输缓存、多轮状态的失效策略，以及后台任务执行顺序与周期均沿用现有实现。
视频任务由编排包管理，任务锁与可变字段封装在包内；HTTP 通过状态快照读取结果。

## 模型校验与额度查询

严格模型校验默认关闭。协议层按模型 hex 归组比较自报显示名，编排层检查配置并返回携带证据的错误，
HTTP 层统一映射为额度不足分类。输出保持实时转发，校验发生在生成返回后；流已打开时以失败事件结束。
校验覆盖有模型证据的已知文本模型，别名和思考档位按基础模型判断，其余情况放行。
模型不匹配直接结束本次请求；账号鉴权失败仍仅按 401/403 计数。

额度查询的协议请求与数组解析在上游协议包中，账号和出口的只读选择在资源池中，
实际账号身份的缓存与同请求合并在编排层中。HTTP 端点沿用管理鉴权，查询失败返回可读错误。
缓存键包含账号、Cookie 与代理地址的摘要；管理查询与选号共用 20 秒的新鲜度，查询失败时清除服务端快照。全局锁用于缓存与并发查询状态的读写。
返回指标深拷贝，并在每次读取时重算重置倒计时。

额度选号由编排层计算优先级，资源池在原子选号期间读取分数。分数相同时沿用健康度与轮转顺序；选号完成后，编排层按需补查缺失或过期的快照，最多三路并发，同身份每 20 秒最多启动一次。多轮续接沿用会话账号。
查询为只读操作，账号轮转、健康度、出口绑定与生成限流计数保持原值；出口选择遵守代理冷却与直连回退设置。

## 管理前端

[HTML 外壳](../web/admin/index.html)声明本地资源与挂载点，页面业务由脚本实现。
[样式](../web/admin/styles/)按基础变量、布局、通用组件、业务页面和响应式规则组织；
[脚本](../web/admin/scripts/)分公共请求与格式化、通用弹窗与错误、业务页面、导航外壳和登录启动。
Cookie 池进一步分视图、额度查询、导入和账号操作；设置分视图、字段清单、运行时表单和 API Key 操作。
原生脚本通过 HTML 中的延迟加载顺序管理依赖；公共能力先加载，启动脚本最后执行。
前端使用原生脚本与样式，全部资源随二进制嵌入，静态文件通过只读嵌入文件系统提供。
手机界面使用底部导航、顶部退出入口和单层滚动；表格复用真实表头标签展开为纵向信息，
账号标签和额度优先呈现，弹窗在底部展开，操作区为触摸交互留出空间。

Cookie 池页面可见时逐轮查询额度，每轮最多三路并发，完成后按配置间隔继续。切页、隐藏标签页或退出登录时取消在途请求并暂停轮询，返回可见页面后恢复。
每行显示两档剩余额度、重置时间与刷新按钮。刷新失败时保留页面内的上次成功结果，用警告色文字标注缓存及失败原因；恢复成功后更新数据。首次查询失败与缺失档位各自显示对应状态。

## 测试

所有测试与测试辅助代码集中在 [tests/](../tests/)，按职责分组。

- 测试按职责分组，跨账号、出口、存储与启动语义的回归放在 [集成测试](../tests/integration/)。
- [公共辅助](../tests/testutil/) 为各测试进程独立创建临时 SQLite，清除生产连接串的环境覆盖，关闭连接后清理目录。
- 测试通过导出业务能力和可观察输出验证行为，锁、状态表和正则保持私有。
- 管理输出通过请求记录器调用生产处理函数验证。
- 数据库故障回归继续使用真实 SQLite 约束、触发器和事务，覆盖写入失败及完整回滚。
- [真实上游探针](../tests/probes/) 默认跳过，仅在显式设置其环境变量时运行。
- 解析 fixture 跟随对应测试，例如 [搜索解析数据](../tests/gemini/testdata/)。
- [浏览器检查](../tests/web/check_ui.py)调用生产渲染函数验证 DOM 与转义，生成桌面和窄屏截图。
  本机 HTTP 夹具提供额度响应，覆盖轮询、失败缓存、恢复、并发和页面生命周期。
  Chromium 通过原生设备模拟验证实际视口，默认结束后清理截图；人工检查可用 `--keep-artifacts` 临时保留后清理。
- 管理资源测试遍历 HTML 引用，并核对运行时配置字段与前端字段清单，防止拆分后漏加载或保存丢字段。

在仓库根目录运行：

```sh
go build ./...
go test ./... -count=1
go test ./... -shuffle=on -count=3
go vet ./...
python tests/web/check_ui.py
```

需要生产包覆盖率时，应显式设置覆盖范围；默认覆盖率只统计测试所在的包：

```sh
go test ./tests/... -coverpkg=./internal/...,./web/... -coverprofile=coverage.out
```

从仓库根目录构建可执行程序或镜像：

```sh
go build -o gemrelay ./cmd/gemrelay
docker build -f build/package/Dockerfile -t gemrelay .
docker compose -f deployments/docker-compose.yml up -d
```

Compose 默认拉取 `ghcr.io/yoyo-514/gemrelay:latest`，监听 `0.0.0.0:8083`，管理员令牌通过环境变量或环境文件提供。
本地源码构建作为注释选项保留，启用时按配置说明切换镜像与拉取策略。构建上下文是仓库根目录，
配置中的容器定义路径相对于该上下文；相对绑定挂载路径则相对于部署文件所在目录。
GemRelay 使用独立的数据卷与数据库文件名。旧项目的数据保留在原位置，由使用者自行备份和迁移。

Dockerfile 用于 CI 发布镜像与可选的本地源码构建。构建上下文采用允许列表，仅包含生产入口、内部代码、模块清单与嵌入资源；本地配置、凭据和数据库留在宿主机。
配置读取范围为显式路径或当前工作目录。默认数据库为 `./data/gemrelay.db`，Compose 卷名为 `gemrelay-data`。
HTTP 路由、响应字段、数据库结构和网络回退策略保持原有约定。
